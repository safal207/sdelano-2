# RA-001 — BitOS Return Architecture / Return Engine Foundation

**Статус:** проект контракта, не активирован. Первая экспериментальная площадка: «Сделано 2.0», Draft PR #3. Базовый коммит: `eb09e26a8ec25f200e1f7e3544ae5b77350ad055`. Версия 1.0, игровой кошелёк, main и публикация остаются без изменений.

## 1. Принцип и границы

Не удерживать человека; создавать причины добровольно вернуться. Цикл: потребность → полезное действие → реальная ценность → положительный опыт → возможность продолжить → добровольное возвращение. Эмоциональная память, ассоциативное обучение, внимание и предвкушение — гипотезы объяснения, не доказанный нейрофизиологический эффект продукта. Не выводить настроение, диагнозы или уязвимости из действий человека.

Return Engine отвечает за релевантный следующий шаг и измерение возврата. Не начисляет XP, деньги или монеты, не меняет цены, не выполняет задачи, не отправляет сообщения, не создаёт обязательства. Отсутствие пользователя не является ошибкой.

## 2. Универсальный контракт v0 (предложение)

Чистая функция `recommendReturn(snapshot, context, policy)` → `{ kind, reason, action, evidence }`, где kind = none | resume | start | offer, reason — стабильный код, action — разрешённое адаптером действие, evidence — минимальная фактическая опора. Не возвращать персональные данные в диагностике. Функция детерминирована при одинаковом входе; время передаётся явно. Ошибочные данные → none, без побочных эффектов.

Snapshot: product, schemaVersion, lastUsefulActionAt (nullable), lastVisitAt (nullable), pendingCount (nullable), consent/permissions, product-specific eligibility flags. Context: now, localCalendarDay, entrySource (direct/referral/reminder/campaign/unknown), currentIntent (если явно известен). Policy: minGap, available actions, channel permissions. Идентификаторы и тексты задач остаются в адаптере продукта, а не в универсальном контракте.

Приоритет: текущая явная потребность > незавершённое полезное действие > возможность начать новое > none. Предложение необязательно, не блокирует основное действие, без искусственной срочности и ложного дефицита. Для коммерческих офферов обязательны уместность, известная цена, бюджет при наличии согласованной информации и возможность отказаться. Никакого автоматического повышения цены.

## 4. Первый эксперимент: Сделано 2.0

Существующий код уже содержит `RETURN_AFTER_MS = 24h`, `lastTaskActivity`, контекстный next-action, First Three Wins, локальный пилот и D1 по календарному дню. Не дублировать этот функционал; переиспользовать существующие состояния и CTA.

| Сценарий | Текст / решение |
| --- | --- |
| Новый пользователь | «Начни с одного дела»; без приветствия о возвращении |
| Возвращение после >=24h, есть активное дело | «Продолжи своё дело»; CTA к существующей задаче |
| Возвращение после >=24h, все дела закрыты | «С возвращением. Начни с одного дела, если хочешь»; CTA к полю ввода |
| История есть, список очищен | мягкое начало без ложной статистики и нового первого достижения |
| Короткий перерыв / текущая сессия | обычный сценарий, без нового приветствия |
| Время недостоверно, хранилище недоступно | обычный список задач, без утверждений о прошлом |
| Вход по приглашению | приоритет приглашению и первому действию, без конкурирующих CTA |

Первый эксперимент: показать контекстный возврат в существующем слоте next-action, без дополнительного модального окна, звука, награды, уведомления, streak или потери стадии. Существующий лисёнок не требует внимания; его анимация остаётся привязана к подтверждённым действиям. Повторный reload не создаёт достижение. Возврат и возобновление — разные события.

## 5. Измерение

Локальный пилот, только добровольный экспорт агрегатов. Не сохранять тексты задач, имена, контакты, точные timestamps или идентификаторы в отчёт. Время может использоваться локально для календарного расчёта. Не включать новые сетевые запросы; существующая endpoint-аналитика не является разрешением на расширение передачи данных. Источник входа unknown, если не доказан; отсутствие UTM не доказывает отсутствие внешнего напоминания. Не считать reload новой уникальной персоной.

| Метрика | Определение |
| --- | --- |
| Activation | участники, выполнившие первое дело / новые участники пилота |
| D1/D7 visit | участники с посещением в локальный календарный день +1/+7 от старта / участники соответствующей полностью наблюдаемой когорты |
| D1/D7 useful return | то же, но с выполненным полезным действием в этот день |
| Direct-entry useful return proxy | полезный возврат при наблюдаемом прямом входе / полностью наблюдаемая когорта; источник unknown отдельно |
| Resume conversion | завершили существовавшую активную задачу в сессии / увидели релевантное предложение продолжения |
| Third win | достигли трёх одновременно завершённых дел / новые активированные участники |
| Referral activation | приглашённые участники, завершившие своё дело / открывшие приглашение; измерять в рамках наблюдаемого пилота |
| AOV / Frequency / LTV | для торговли: выручка / заказы; заказы / покупатели за период; накопленная ценность клиента за заданный горизонт, предпочтительно маржинальная прибыль с учётом затрат |

Показывать числитель, знаменатель, горизонт, размер выборки, пропуски и ограничения. D1 календарный не равен 24-часовому порогу UI. Для существующих пилотных участников без исторических данных новые метрики неизвестны, не ноль. Опрос по желанию: «Что побудило вернуться?»; не считать ответ доказательством нейромеханизма. Пилот из 10 человек — качественный сигнал, не статистическое доказательство роста удержания. Сравнение baseline vs variant только при сопоставимых когортах; гипотезы и критерии фиксируются до наблюдения. Пока ни одного результата нового эксперимента нет.

## 6. QA и выпуск

RA-002 — чистый decision engine в engine-lab, unit tests для таблицы состояний; не подключать к UI по умолчанию.
RA-003 — изолированный opt-in адаптер и тесты Chromium/Firefox/WebKit 320/390/1280: новый пользователь, возврат с активным делом, полностью закрытый список, 23:59:59/24:00:00, смена локального дня, DST, будущее время, reload, несколько вкладок, legacy, запрет хранения, реферальный вход. Проверить, что основной CTA доступен, нет лишних окон, не начисляется XP, не меняются кошелёк и записи задач, не отправляются новые сетевые события.
RA-004 — добровольный пилот с агрегатами, D1/D7, качественная обратная связь; сравнение с исходной версией. Отдельное разрешение на публикацию.
RA-005 — перенос универсального контракта в BitOS после проверки на «Сделано» и согласования границ коммерческих адаптеров.

Критерии допуска: тесты чистой функции и браузерные регрессии зелёные; визуальный осмотр; ни одной новой автоматической транзакции/уведомления/потери прогресса; неизменность существующих начислений; возможность отключить эксперимент. Никакого мержа или деплоя в рамках RA-001.
