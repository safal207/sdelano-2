# BitOS Game Engine 0.1 — архитектурный контракт

**Состояние:** DESIGN + экспериментальная лаборатория. Пока НЕ интегрировано в рабочую игру.

## Миссия

Универсальный движок преобразует **проверенные полезные действия** в прозрачный прогресс. Он не должен превращаться в принудительную активность, виртуального питомца или бесконечные напоминания.

Поток:
1. Приложение фиксирует реальное событие.
2. Доменный адаптер проверяет основание события.
3. Правила версии N определяют допустимую награду.
4. Идемпотентная транзакция добавляется в журнал.
5. Производные селекторы вычисляют XP, монеты, уровни и состояние персонажа.
6. UI показывает короткую обратную связь. Аналитика оценивает пользу, а не число кликов.

## Границы модулей

- **Core**: чистые функции валидации событий и переходов; без DOM, времени компьютера, network, localStorage и Telegram.
- **Policy**: версия правил, ограничения частоты, дедупликация, дневные лимиты, условия фокуса и обучения.
- **Ledger**: append-only операции; ключ идемпотентности actorId + eventId + ruleId + ruleVersion; повторный запрос не выдаёт награду.
- **Projection**: XP, баланс, достижения, уровни и рост лисёнка вычисляются из проверенных операций, не из произвольных цифр в клиенте.
- **Adapters**: todo, cafe, education, Telegram Mini App. Преобразуют подтверждённые действия в события, не меняя ядро.
- **Ports**: EventStore, Clock, Identity, RewardLedger, PurchaseVerifier, PermissionGate, Notifications, Analytics, FeatureFlags.

## Протокол события (предварительный)

```json
{
  "eventId": "opaque-unique-id",
  "actorId": "pseudonymous-user-id",
  "kind": "task.completed",
  "source": "todo",
  "subjectId": "task-id",
  "occurredAt": "2026-11-23T12:00:00Z",
  "evidence": { "localActionId": "opaque-action" }
}
```

События: task.completed, task.undone, focus.claimed, lesson.applied, order.paid, order.refunded. **order.paid** можно подтвердить только на сервере после проверки платежа; клиентский флаг не является доказательством. Возвраты отражаются сторно, журнал не переписывается молча.

## Контракты тестирования

1. Один eventId не даёт второй награды, даже после reload, undo/redo, импорта, повторного запроса API и конкурирующих вкладок.
2. Нельзя начислять награду другому actorId или за неподтверждённое событие.
3. Баланс выводится из операций и защищён от некорректных/отрицательных/слишком больших начислений.
4. Фокус учитывает только подтверждённое видимое время; фоновая пауза не должна начислять XP.
5. Новые правила версионируются, меняют старые записи только через явную миграцию.
6. Лисёнок растёт как отражение прогресса пользователя; без потребности в уходе, наказаний и автономных просьб.
7. Поделиться достижением — opt-in, а тексты личных задач приватны по умолчанию.
8. Тесты должны проверять повторные события и конкурентную обработку перед подключением к реальному кошельку.

## Изоляция от существующих данных

Сейчас игровой прототип использует `todo-list.tasks.v1` и `sdelano.game.v1`. Их нельзя молча переименовывать, мигрировать или очищать. На другом домене localStorage первой версии не доступен: будущий перенос — только с согласия через верифицированный JSON или авторизованный backend.

`engine-lab/event-ledger.mjs` — лабораторный reference reducer, **не производственный защищённый кошелёк**. Его 4 теста не заменяют CI игрового прототипа и проверку антифрода сервера.

## Следующие итерации

1. Подтверждённый перенос текущего runtime и существующих Playwright тестов.
2. ADR по модели событий и детерминизму; shadow-mode без записи в экономику.
3. Антидублирование при sync и небезопасных клиентах; property-based и concurrency тесты.
4. Отдельные адаптеры cafe/education, затем Telegram Mini App только после серверной верификации identity/initData.
5. Оценка реальной пользы в эксперименте: завершение дел, D1/D7 retention, добровольная удовлетворённость; нельзя оптимизировать лишь игровое время.
